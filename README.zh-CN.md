# Device Selective Sync

[English](README.md) · 简体中文

选择哪些 Obsidian 插件可以在电脑、手机和 iPad 上同步。你可以在电脑上统一设置，也可以在手机或 iPad 上选择本机需要的插件。

本插件免费，采用 [MIT 许可证](LICENSE)。需要 **Obsidian 账号和付费的 Obsidian Sync 订阅**，使用你已经为仓库配置的官方 Sync 服务。本插件是独立社区项目，并非 Obsidian 官方产品。当前版本为 **0.3.4，实验版本**：适配 Obsidian 1.13.7，并且需要通过本机兼容检查。手机和 iPad 的真实同步尚未完成验证，请先用测试仓库体验。

[代码仓库](https://github.com/Lywooye/obsidian-device-plugin-sync) · [下载发布版本](https://github.com/Lywooye/obsidian-device-plugin-sync/releases)

公开名称改为 **Device Selective Sync**，原名 Device Plugin Sync。插件 ID 仍为 `device-plugin-sync`。原有 `Device Plugin Sync/Policy.md`、`Device Plugin Sync/Installations/` 路径及本机设置保持不变，无需迁移或重新选择。

## 先学会这两件事

- **勾选：允许这个插件在该设备同步。** 其他 Sync 设置仍然有效。
- **不勾选：阻止这个插件的文件在该设备上传和下载。** 已经装好的插件仍然保留；只有你另外确认清理，它才会从本机移走。

首次建立清单时，电脑默认全选，手机和 iPad 默认全不选。每台设备都有“全选”和“全不选”。升级不会重置你已保存的选择。0.3.0 还可以根据**新插件从哪台设备安装**，自动加入清单并设置它的同步范围，规则见下节。

## 第一次使用

### 在管理电脑上

1. 安装并启用本插件，打开“设置 → Device Selective Sync”。
2. 点击“创建同步清单”。这台电脑负责维护设备名单和插件清单。
3. 点击“选择各设备的插件”，给各台设备勾选需要同步的插件，然后点击“保存清单”。
4. 选择这台电脑在表格中对应的设备。
5. 点击“查看并应用”，检查本机的变化，再点击“确认应用”。**手动改动已有插件的选择后，还需要在每台设备分别应用。**
6. 应用成功后，可以选择是否清理本机不再同步的插件。不清理也可以正常使用同步选择功能。

### 在手机或 iPad 上

1. 等待本插件和 `Device Plugin Sync/` 文件夹中的清单与安装记录同步完成，在移动端启用本插件。
2. 打开本插件设置并刷新。手机选择手机对应的设备，iPad 选择 iPad 对应的设备；不同设备不要共用同一个位置。
3. 查看兼容状态。检查通过后，**请本人在这台设备上打开“允许在这台手机或平板上修改同步设置（实验功能）”**。安装更新不会替你打开这个开关。
4. 点击“选择本机插件”，勾选需要的插件。这里可以看到共享清单中已登记的全部插件，即使某个插件尚未下载到手机。
5. 点击“保存并应用”，检查预览，再点击“确认保存并应用”。
6. 等待 Sync 完成，再到另一台设备修改选择。

0.3.4 只更新移动端的 Sync 适配。自动识别新安装和清理本机插件仍有独立检查，在手机或 iPad 上可能仍不可用。识别不可用时，可以为确实在本机安装的插件使用“登记本机安装的插件”；清理检查不通过时请保留文件，不要绕过检查。

如果手机还显示旧界面，可以只停用再启用 Device Selective Sync。不要因为看见新的表格版本，就认为本机设置已经应用；以本机的应用结果为准。

首次设置时，可以先在官方 Sync 设置中暂停同步，确认本机选择已经应用后再继续。暂停不能撤回已经开始的传输，也不能阻止首次安装本插件前其他插件已经下载。

## 新安装的插件自动设置同步范围

“自动设置新插件的同步范围”默认开启，开关只影响当前设备。它识别**本插件正在运行时，通过 Obsidian 官方社区插件入口新安装**的插件；自动把新插件加入共享清单，各设备收到后只调整这个新插件的同步设置。

| 新插件在哪里安装 | 所有电脑 | 安装它的手机或 iPad | 其他手机或 iPad |
| --- | --- | --- | --- |
| 电脑 | 允许同步 | 不适用 | 不同步 |
| 手机或 iPad | 允许同步 | 允许同步 | 不同步 |

例如，手机新装插件的来源登记完成后，电脑也允许接收它，其他手机和 iPad 默认不接收。移动端自动识别安装可能仍不可用，此时用“登记本机安装的插件”确认来源。以后你仍可在选择表中改。**已有插件的选择、你手动设置过的选择，以及插件更新，都不会被这套默认值重置。**

电脑、手机和 iPad 都需升级到本插件 0.3.0 或更新版本；旧版不会自动处理新增插件。每台设备都需要先完成以下设置：

1. 选择这台设备在清单中的名称，并保持 Device Selective Sync 启用。
2. 开启“自动设置新插件的同步范围”。
3. 在官方 Sync 中开启社区插件文件和插件设置的同步，并让 `Device Plugin Sync/Policy.md` 与 `Device Plugin Sync/Installations/` 正常同步。
4. 通过本机兼容检查。手机和 iPad 还需要分别开启“允许在这台手机或平板上修改同步设置（实验功能）”。

本插件会在收到文件变化时以及定期检查新记录。满足条件后，只自动应用**本机以前没登记过的插件 ID**，不会顺便应用已有插件的手动改动，也不会弹出清理窗口、删除文件或修改启用列表。新插件允许同步不等于自动启用它。

**从旧版本升级，或本机第一次收到共享清单时，只记下当时已有的插件作为起点，不会替你应用旧选择。** 原来没有应用的选择仍需“查看并应用”。关闭自动处理后，也可以继续手动选择、保存和应用。

通过 BRAT、手工复制安装，或在 Device Selective Sync 没运行、自动处理关闭、尚未创建清单或绑定设备时安装的插件，无法可靠判断来自哪台设备。请先完成清单和设备设置。重新开启“自动设置新插件的同步范围”后，点击“登记本机安装的插件”，勾选尚未登记的插件，再点击“确认这些插件是在本机安装的”；不要把刚从别处同步过来的插件误登记为本机安装。已经登记的插件不会被重复登记覆盖。

如果未绑定设备、兼容检查未通过、手机实验功能关闭，或文件读写失败，界面会显示等待原因。处理后点击“检查新插件”重试。它不会跳过保护条件强行写入。

自动处理仍是**收到信息后再执行**。插件文件、安装记录和共享清单可能按不同顺序到达，因此不能保证不需要的插件一次都没下载过，也不能撤回进行中的传输。已经下载的文件会保留，需要时再手动清理。

安装来源记录位于：

```text
Device Plugin Sync/Installations/<安装来源设备的标识>/<插件 ID>.md
```

记录按来源设备分开保存，减少不同安装互相覆盖；各设备读取记录后，只将清单中尚不存在的插件 ID 加入 `Policy.md`。这不是跨设备锁，同一插件已有的选择优先，也不能保证多台离线设备同时编辑不会冲突。请继续避免同时手动编辑清单。

本轮未在真实设备上安装新插件来验证这条自动流程。项目测试与接口检查不能代替手机、iPad 和实际网络同步验收。

## 应用后清理本机插件

手动应用成功后，本插件会询问是否清理**本机已经安装、但这台设备选择不再同步**的插件。你可以点击“保留本机插件”跳过；需要清理时，逐个勾选，再勾选包含本机设置的确认项，最后点击“移走所选插件（保留备份）”。默认不会选中任何插件。

清理对象是整个插件文件夹，通常包括插件程序和 `data.json` 等设置文件。请先确认是否需要保留这些设置。Device Selective Sync 自身不会出现在清理名单中。

清理采用“移走并保留备份”，不是永久删除，也不会释放这些文件占用的空间。文件夹会移到当前仓库的隐藏目录：

```text
.device-plugin-sync-trash/<本次清理的编号>/<插件 ID>/
```

执行前，请在官方 Sync 中**暂停同步，并等待当前传输结束**。如果清理窗口挡住了设置，先点击“保留本机插件”，到官方 Sync 设置中暂停，然后回到本插件点击“选择要清理的插件”。这样可以降低进行中的同步把本机清理误当成删除的风险。本插件不会替你暂停或继续同步；检查结果后，再由你恢复同步。运行中的所选插件会在本机停止运行，其他插件保持原样，不改写共享的插件启用列表。

需要找回时，在“找回清理过的插件”中点击“查看本机备份”，找到对应插件后点击“放回这个插件”。同样先暂停同步、等待传输结束；该插件还必须处于本机不同步状态。若已经勾选为允许同步，先取消勾选并应用。找回会将备份移回原位置，不覆盖已经存在的文件夹、不取消同步限制，也不自动启用插件。找回操作本身不会启用插件，但因为原来的启用列表没有改变，**之前已启用的插件可能在重启 Obsidian 后再次加载**。请在社区插件设置中检查，确认文件和设置无误后，再决定启用状态或是否允许同步。

本插件会检查原目录已被排除、备份位置不会参与 Sync，并核对所需接口。任何检查失败都会停止清理或找回。清理使用额外两项内部函数检查；即使清理暂不兼容，只要同步设置检查通过，仍可正常应用同步选择。不要把备份目录改名、加入其他同步工具，或手动将它纳入同步。

如果中途出现错误，部分插件可能已经移走，或文件已移动但 Obsidian 的列表尚未刷新。请查看结果中已完成和未确认的项目，再检查“查看本机备份”；不要仅凭一条报错就认定没有改动。必要时重新打开 Obsidian 刷新插件列表，确认结果后再恢复 Sync。

这里的“清理”与“停止同步”是两件事。停止同步本身不会删文件，清理也不会修改共享表格里其他设备的选择。清理前会再次检查本机的同步限制；检查不通过就停止。

这是本机操作，不能把成功提示当成其他设备或云端文件已核验的证明。正在进行的传输以及之前已经同步的更改，不在本插件的撤回范围内。

## “重新同步”和故障处理分别做什么

| 功能 | 适合什么时候使用 | 实际效果 |
| --- | --- | --- |
| 重新允许这些插件同步 | 想撤销本插件给这台设备设置的限制，或准备停用本插件 | 先预览，再取消本插件添加的限制。你原来手动设置的限制保留。它不会恢复被清理的文件，也不会恢复历史设置。 |
| 查看本机备份 → 放回这个插件 | 想拿回刚才移走的插件和设置 | 在暂停同步、目录仍被排除时，把本机备份移回空的原位置。不覆盖文件，不主动启用或恢复同步；之前已启用的插件重启后可能再加载。 |
| 检查上次操作 | 上次应用报错、崩溃，界面提示操作尚未完成 | 对照当前 Sync 设置，判断上次停在何处，并修正本插件的记录。不会再次应用，也不会修改 Sync 设置。完成后重新预览。 |
| 重置本插件的管理记录 | 记录确实无法恢复，且你愿意以后手动处理留下的限制 | **只清记录，现有 Sync 限制还在。** 本插件之后无法辨认哪些限制是它加的。通常不需要使用。 |

重新允许同步后，Sync 可能下载远端文件、更新本地插件或处理远端删除。它不等于“恢复到清理前”。清理文件的找回方法见清理结果提示。

**停用或卸载本插件，不会自动取消已经设置的 Sync 限制。** 如需取消，请先使用“重新允许这些插件同步”，检查结果后再停用。

“故障处理（通常不需要）”默认折叠，正常使用时不用操作。

如果上次操作的结果与“执行前”和“预计执行后”都不同，本插件会要求你检查官方 Sync 设置，不会替你猜测或覆盖设置。清除 Obsidian 本地数据、重装设备或重新配置仓库，也可能让本插件失去原来的管理记录。

## 中文和英文

界面提供简体中文和英文，可以在本插件设置中选择“跟随 Obsidian / 简体中文 / English”。语言选择只影响当前设备。

“跟随 Obsidian”使用 Obsidian 的界面语言：中文使用简体中文，其他语言使用英文。新安装默认跟随 Obsidian；旧版用户升级后保留中文，可随时改选。

中文说明在本文件，英文说明在 [README.md](README.md)。插件名称、插件 ID、用户设置的设备名称和路径保持原样。

## 你需要知道的边界

### 它只管理插件文件的同步

本插件为官方 Sync 添加或取消具体插件目录的同步限制。默认目录为 `.obsidian/plugins/<插件 ID>`；如果设备使用了自定义配置文件夹，会使用该设备的实际路径。

- 未确认清理前，不修改已有插件文件、设置或启用状态。
- 不负责安装或更新插件。
- 不接管“已启用社区插件列表”的同步。文件是否同步、插件是否启用，是两项独立设置。
- 勾选一个插件不会强制下载它，也不会越过你原来设置的其他限制。例如你已排除整个插件目录，勾选其中一个插件不会取消这个限制。
- 已有插件的手动选择仍需刷新、预览和确认。开启自动处理时，只有新登记的插件 ID 会自动应用；不会追溯替你应用旧选择。

要传输允许同步的插件及设置文件，需要在官方 Sync 中开启社区插件文件和插件设置的同步。是否同步各设备的启用列表，请在官方 Sync 中另行设置；自动处理不会改写该列表。

### 手机读取共享清单，不会实时读取电脑硬盘

共享设置保存在普通笔记 `Device Plugin Sync/Policy.md` 中，新安装来源记录保存在 `Device Plugin Sync/Installations/`。请让这两部分正常同步，不要排除它们或所在文件夹。

清单包含设备名称、设备标识、插件名称和插件 ID，以及每台设备的选择；安装记录还包含安装来源。它们都不包含本机清理备份。本机设备选择、操作记录、兼容确认和语言设置保存在当前设备。

管理电脑可以手动维护全部设备和插件清单。手机、iPad 手动编辑时只能修改自己对应的位置。已识别的新安装会自动登记；未识别的安装需要确认来源，或在管理电脑重新打开选择表并保存。手机显示的是收到的共享清单，不会实时读取电脑硬盘。

### 避免两台设备同时编辑

请先等 Sync 完成，再编辑；保存后也等 Sync 完成，再换设备。

保存时，本插件会发现**已经到达本机**的设置变化并要求重新打开。它不能锁住另一台离线设备，不能保证同时编辑不会冲突。遇到冲突时，先检查共享文件合并后的选择，再逐台预览并应用。

手机保存选择和修改本机 Sync 设置是两个步骤。若前一步成功、后一步失败，会提示“选择已保存，但本机尚未应用”。先按界面处理未完成的操作，再重新预览。其他设备收到已有插件的新选择后也不会自动应用；只有首次登记的新插件走上述自动流程。

### 为什么 Obsidian 升级后可能不能应用

Obsidian 尚未提供本插件所需的公开 Sync 接口，所以当前版本使用内部接口。内部接口可能随升级改变，甚至同一版本在不同平台也可能不同。

0.3.4 为电脑和移动端分别保存一套兼容指纹，根据 Obsidian 实际运行的平台选用。版本、该套指纹中的全部 12 个方法，以及隔离的文件过滤检查都必须通过，不会从两套记录中挑选匹配项混用。发现不匹配就禁止修改 Sync 设置。此时仍可查看选择和预览，**官方 Sync 本身不会因此暂停**。已经保存的限制仍由 Sync 执行，新选择尚未生效。

移动端这套指纹来自官方 Android 1.13.7 构建的核验，其 12 个 Sync/过滤方法指纹也与 iPhone 1.13.7 诊断截图一致。这不等于核验了完整 iOS 源码，也不等于手机或 iPad 的实际同步已经通过。来源、摘要、差异审查和限制见 [兼容性核验记录](docs/compatibility-review.md)。

自动识别新安装和清理本机插件各有独立检查，本次没有修改。识别不可用时可手动登记，清理被阻止时请保留文件。自动处理与手动应用都不会绕过 Sync 检查和移动端实验开关。

适配新版本需要开发者检查实际实现和行为，不能只修改版本号或跳过检查。移动端即使显示 1.13.7，也需要在各自设备通过检查，并手动开启实验功能。

当前测试不等于真实手机/iPad、联网同步、应用重启后保存以及进行中传输的验证。具体测试范围和后续验收见 [验证记录](docs/test-results.md) 与 [设备验证说明](docs/device-validation.md)。

### 数据处理与内部接口说明

本插件不会直接发起外部网络请求，没有遥测、分析统计或自建上传服务。插件文件、设置、共享清单和安装记录由 Obsidian Sync 使用现有账号与仓库配置传输。运行时插件不访问当前仓库以外的文件。

其他插件的 `data.json` 等设置文件可能保存 API 密钥或登录信息。允许该插件目录同步时，这些设置可能随官方 Sync 原有功能一起传输。本插件不会替你隐藏密钥，也不把程序文件和设置文件分开处理。清理时生成的本机备份同样保留完整设置。

供审核者参考：本插件使用非公开 Sync 方法读取、保存排除项；确认清理后使用非公开插件管理方法停止运行实例；通过临时包装非公开社区插件安装方法识别新安装。卸载时，只有入口仍是本插件的包装，才将它还原。这些接口没有官方公开支持或长期稳定承诺。版本与方法指纹不匹配时会停止相关功能；检查用于识别兼容变化，不是抵御其他插件篡改的安全边界。

原生源码测试从开发者本机的桌面构建或指定的官方 Android 源码中读取方法，在内存中的隔离对象上执行。仓库和发布附件只包含指纹与测试工具，**不分发 Obsidian 原生源代码、应用包或提取出的原生测试样本**。此类测试需要本地兼容构建，不验证真实 IndexedDB、冷启动、移动设备或网络传输。

## 手动安装

0.3.4 已完成社区目录自动审核，公开页面显示 Review: Satisfactory；这不等于真实设备同步验收。打开 [插件市场页面](https://community.obsidian.md/plugins/device-plugin-sync)，点击 **Add to Obsidian** 即可进入安装页面。如需手动安装，可以从 [GitHub Releases](https://github.com/Lywooye/obsidian-device-plugin-sync/releases) 下载运行文件或安装 ZIP，也可以自行构建 `dist` ZIP：

1. 先停用已有的 Device Selective Sync。
2. 将 ZIP 中的三个运行文件放入仓库的实际配置目录：

   ```text
   .obsidian/plugins/device-plugin-sync/
   ├── main.js
   ├── manifest.json
   └── styles.css
   ```

3. 若使用自定义配置目录，请将 `.obsidian` 换成实际名称。
4. 在 Obsidian 的“设置 → 社区插件”中启用 Device Selective Sync。

不要多套一层 `dist` 文件夹。移动端手动安装需要能写入仓库的实际配置目录；把 ZIP 放进笔记目录不会完成安装，iOS 的“文件”应用也不一定能访问隐藏配置目录。

各端使用相同配置目录时，可以通过官方 Sync 将电脑已安装的本插件传到移动端，再单独启用。这个过程也可能传入其他插件，不能保证首次下载前就将它们拦住。使用不同配置目录时，不要假定本插件会自动出现在另一设备上。

## 构建与以后发布

需要 Node.js 22 或以上、npm 和 `zip` 命令。在源码目录运行：

```sh
npm ci
npm run package
npm run test:native
```

`package` 会检查类型、运行测试、构建并生成安装包。`test:native` 只读检查本机安装的 Obsidian 桌面版本，默认 macOS 路径为 `/Applications/Obsidian.app/Contents/Resources/obsidian.asar`。其他路径可这样指定：

```sh
npm run test:native -- --asar /absolute/path/to/obsidian.asar
```

如需检查本次核验的移动端源码，请将环境变量指向官方 Android 1.13.7 APK 中 `assets/public/app.js` 的本地副本：

```sh
OBSIDIAN_MOBILE_APP_JS=/absolute/path/to/app.js node scripts/check-mobile-native.cjs
OBSIDIAN_MOBILE_APP_JS=/absolute/path/to/app.js node --import tsx --test tests/mobile-adapter.test.ts
```

检查会先核对整个 `app.js` 的 SHA-256，再检查方法。[兼容性核验记录](docs/compatibility-review.md) 列出了官方来源与预期摘要。项目仅保存指纹和工具，不分发 Obsidian 应用包或原生源代码。

公开发布已为 [Lywooye/obsidian-device-plugin-sync](https://github.com/Lywooye/obsidian-device-plugin-sync) 准备 [MIT 许可证](LICENSE)、中英文说明和运行附件。GitHub 发布与 Obsidian 社区目录审核是两件事。

当前 [官方提交说明](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin) 要求通过 Obsidian Community 网站登录账号、绑定仓库所有者的 GitHub 账号后提交，旧的 `obsidian-releases` PR 模板已不是当前入口。目录会审核仓库和发布版本；只有收到实际审核结果后，才能称为已上架。
