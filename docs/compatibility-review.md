## 精确指纹策略

对 `Function.prototype.toString.call(fn)` 的 UTF-8 字节计算 SHA-256。不要压缩空白、修改标识符或忽略任意代码差异。版本必须与清单精确一致，所有列出的指纹必须一致。0.3.4 根据实际运行平台整套选用 `src/native-profile.json`（桌面）或 `src/native-mobile-profile.json`（移动），不逐项兼容、不混用两套指纹。

当前覆盖 Sync 的目录 setter、改变过滤器、设置 dirty 标志、安排保存、实际保存、请求同步及加载数据方法；覆盖过滤器的带缓存与无缓存判断、缓存清除、插件文件判定、改变过滤条件方法。

任何未知版本、函数不匹配、Web Crypto 不可用或结构异常均只读。禁止运行时自动更新允许列表，禁止根据相近版本推测兼容。指纹比较是变化探测，不能证明全部调用依赖、底层存储或系统行为相同，也不是抵御恶意插件篡改的安全边界。

首版定位：已知桌面版本可作为实验性适配；移动端默认只读；当本机 API 版本、全部方法指纹与隔离过滤检查通过后，可由用户在本机手动开启实验适配。真实手机和 iPad 同步仍待逐台验收。桌面签名相同也不能单独证明移动平台完成测试。

## 无副作用过滤探针

仅在函数指纹已经匹配后，以过滤器原型建立独立对象；复制 `configDir`、`ignoreFolders` 数组、允许类型和允许特殊文件的 Set，并创建新的空缓存。只对该独立对象调用已核验过滤方法，不给真实过滤器追加临时排除，不清除真实缓存。

离线检查包括默认和自定义配置目录，插件的 `main.js`、`manifest.json`、`styles.css`、`data.json`，目录自身、相似前缀、管理插件、启用列表、普通笔记、原有排除项、缓存更新和解除排除后的远端候选恢复。该过滤器会先检查 `ignoreFolders`，再处理插件配置文件规则。

真实实例上的运行时探针也必须保持数组、Set 和缓存独立，并比较未改动的参考结果，避免因为用户本来关闭某类同步而错误宣称其他文件受到本插件影响。

## 保存的准确含义

`setIgnoreFolders(paths)` 是同步方法，返回 `undefined`。它改变过滤器、安排原生保存并请求同步。`forceSaveData()` 只设置 dirty 标志并触发约 2 秒的防抖保存，不提供本次存储完成凭据。因此 `await setIgnoreFolders(...)` 不能证明已经保存。

在当前源码中，可在同一同步调用栈调用 setter 后立即调用原生 `saveData()`，再等待它返回的 Promise；这通过原生保存方法等待内部存储操作完成，无需直接读写数据库。调用前确认 dirty 仍为 true。setter 会同步触发状态事件；若其他监听者已启动保存、导致 dirty 变为 false，随后一次无操作的 `saveData()` 不能被当作本次写入确认。

保存成功后回读过滤器列表，只能标记“原生保存调用完成且内存回读一致”。冷启动后仍一致才是重启持久化验收；文件确实未传输还需双端观察。

重要失败边界：原生 `saveData()` 在等待存储前先把 dirty 设为 false；存储失败会拒绝 Promise，但 dirty 不自动恢复。不能假定已安排的防抖调用一定会重试。失败时应展示“内存规则可能已应用，保存失败或未确认”，保留本次所有权与恢复信息，不标成功、不清空排除、不自动恢复旧列表。请求同步已可能开始，恢复数组无法撤销传输。

## 规则与现有文件边界

原生目录排除影响当前设备上传与下载，并不是只屏蔽下载。它不删除手机已经存在的插件文件，也不修改已安装插件的启用状态。共享启用名单的同步是另一项独立设置。

设置列表改变不能可靠取消已经开始的文件传输。规则文件和插件文件通过同一原生同步系统抵达，首次配置、离线恢复和规则更新可能出现文件先到。界面与文档不得承诺“从未下载过”或“升级自动阻止一切同步”。未知版本只阻止本插件的新写入。

## 重复核验

```sh
node scripts/check-native.cjs
node scripts/check-native.cjs --asar /path/to/obsidian.asar
node scripts/check-native.cjs --app-js /path/to/app.js
```

脚本只读安装包或指定源码，在内存中提取方法并运行独立过滤对象，不调用真实 Sync 实例，不打开或修改仓库配置、插件或 Sync 数据库。`--app-js` 不具备包元数据，版本证据仅来自与当前清单一致的函数指纹；此模式不替代完整安装包版本检查。

升级后应检查公开 API 版本、更新差异、全部私有依赖、离线测试及隔离仓库实际同步。不能仅把清单中的版本号改成新版本。

待完成的验收包括：桌面隔离仓库真实上传与下载、手机与 iPad 各自配置、重启持久化、保存失败恢复、首次同步和离线重连时序。当前报告没有宣称这些已完成。

## 2026-10-01：0.3.0 本机新安装识别

`src/install-observer.ts` 独立核对 1.13.7 的 `app.plugins.installPlugin(repo, version, manifest)`，SHA-256 为 `1d4053d0d73d2dcc35d2d2e8ff53d439351d988d9080a67ceb754cf41ad24d25`。本插件仅包装该入口以观察安装来源，不修改 Sync 过滤方法或它们的指纹检查。Sync 写入文件、普通目录变化、启动加载和已有插件更新都不等于本机新安装。

调用前清单和目录均无该插件、调用后有效 manifest 与非空 main.js 存在，才登记来源；原生方法会吞掉部分安装失败，所以不能只看 Promise 是否成功结束。包装保留原 Promise、接收者、参数和原错误；观察回调失败不改变安装结果。卸载时只有入口仍为自己的包装才还原，避免覆盖其他插件的改动。

每个来源的记录保存在独立普通 Markdown 文件中。自动处理只添加共享清单中尚不存在的 ID，再仅修改本机新出现 ID 的排除规则；旧选择、旧排除路径及共享启用列表保持不变。首次运行建立已有 ID 的本机基线，故不能把升级后的“检查完成”当作旧规则已应用。部分自动处理不记录为整份清单已应用。

该安装入口仍为私有接口。未知版本或方法被替换时，安装本身继续，来源自动识别停止；可用手动登记补充。已有来源记录的处理仍受单独的 Sync 写入检查控制。异步文件到达、离线冲突及进行中的传输仍无零下载保证，真实手机、iPad 和跨设备传输需要独立验收。
