# 易读性审查 / Plain-language review

审查范围：Device Selective Sync 0.1.2 的设置页、选择表、预览、恢复与报错提示；改写目标版本为 0.2.0。

这是按“第一次使用、不了解实现细节”的视角进行的模拟审查，不是真人可用性访谈，也不代表手机真机验收。审查问题是：用户读完后，能否判断要做什么、会改变什么、是否能撤销。

## 主要问题与改写原则

旧版把内部实现中的术语直接放到了主要流程。用户需要先理解管理端、设备槽位、排除项、所有权、原生保存和回读，才能知道一个按钮会做什么。“恢复”同时容易被理解为恢复插件、恢复文件或恢复同步，风险尤其明显。

改写按用户动作命名：选择插件、应用选择、移走文件、找回备份、重新允许同步。一个按钮只描述一个可辨别的结果；限制和例外紧跟相关动作，技术诊断另行展开。

| 旧用语或表现 | 用户容易怎样理解 | 改写后的概念 |
| --- | --- | --- |
| 编辑设备 × 插件规则 / 编辑矩阵 | 需要懂表格或配置文件才能使用 | 选择各设备的插件 / 选择本机插件 |
| 发布新版本 / r4 | 发布软件更新，或已经让所有设备生效 | 保存选择；显示设置版本时解释仅表示共享文件更新 |
| 设备槽位 / 绑定本机 | 要登录、配对硬件，或自动检测手机 | 选择“这台设备是哪一台”；明确由用户手动对应 |
| 排除上传和下载 | 不一定知道排除的是插件程序还是笔记 | 这个插件在本机不再上传或下载；包括插件程序和设置 |
| 新增排除 / 移除排除 | 需要做一次否定转换，难以判断结果 | 停止同步 / 重新允许同步；插件名称优先，路径辅助 |
| 恢复本插件管理的排除项 | 恢复排除状态？恢复被删文件？ | 重新允许这些插件同步；明确不找回文件、不恢复历史设置 |
| 高级恢复 | 以为普通恢复失败后应该继续点 | 故障处理（通常不需要）；默认折叠，仅报错时引导 |
| 核对操作记录 | 类似查看日志，不知道会改什么 | 检查上次操作；明确仅校正记录，不修改 Sync |
| 放弃路径管理记录 | 以为所有限制一起被清掉 | 重置本插件的管理记录；明确限制仍在，以后需手动处理 |
| 原生保存调用完成 / 回读一致 | 无法判断能否继续操作 | 这台设备的选择已应用；持久化与真机验证范围放详情 |
| 12 个内部方法指纹 | 以为用户需要解决代码问题 | 当前版本可用 / 暂不能应用；展开可查看技术原因 |
| 删除本机插件 | 以为只删除程序、不影响设置，或立即释放空间 | 移走插件并保留备份；说明完整文件夹、包含设置、不释放存储 |

这些条目描述审查后的概念；中英文界面的最终文本以 `src/i18n.ts` 为准。

## 三种容易混淆的“恢复”必须分开

1. **重新允许同步**：取消本插件加到官方 Sync 的限制。不会从备份拿文件回来。
2. **找回清理过的插件**：通过“查看本机备份 → 放回这个插件”，把备份移回没有同名文件夹的原位置。仍不同步，操作本身不会启用；因为启用列表未改，之前已启用的插件在重启后可能再次加载。
3. **修复或清空本插件记录**：处理本插件记下的操作状态。不会修改官方 Sync 的限制。

说明中保留一张对照表，让用户按目的选择。清空记录不作为正常操作的后续步骤，避免用户误认为必须“恢复一次、再高级恢复一次”。

## 清理流程的文案要求

- 应用同步选择后，先告知“原有插件仍保留”，再询问是否清理。
- 默认跳过；清理清单默认不选中任何插件。
- 显示插件名称与 ID，允许逐个选。Device Selective Sync 自身不出现。
- 明确是整个文件夹，包含设置；不是只删除 `main.js`。
- 最终动作前要求暂停官方 Sync 并等待传输结束，说明原因；提供实际退路：“保留本机插件”关闭弹窗 → 到 Sync 暂停 → 回来点“选择要清理的插件”。不使用“安全”“绝对不会同步删除”等保证。
- 按钮准确表达“移走并保留备份”；不承诺释放存储。
- 完成后给出可理解的结果及备份位置。中途失败时，分别说明已经完成和未完成的项目。
- 提供独立“找回清理过的插件”入口，不用“重新允许同步”冒充找回文件。
- 找回不覆盖现有目录，保持排除状态，不主动启用；明确原来已启用的插件可能在重启后重新加载。检查文件与启用状态后才由用户决定是否重新同步。
- 文件移动后若列表刷新失败，报错不等于文件未移动；结果应区分已移走、未确认和后续找回路径。
- 额外两项清理接口检查失败时，不把它表述成同步功能全部失效；正常应用仍由原有 12 项 Sync 方法检查独立判断。

## 双语要求

- 简体中文与英文覆盖设置、操作按钮、说明、提示和主要错误。
- 语言选项仅保存在本机，可用自动、简体中文或 English。
- 自动跟随 Obsidian 界面语言；用户设备名称、插件名称、插件 ID、路径不改写。
- `README.zh-CN.md` 与 `README.md` 的使用步骤、清理后果、兼容限制和发布状态保持一致。
- 英文界面不等于已经符合社区审核。当前内部 API 依赖与真实移动端未验收等事项单独列在发布说明中；公开版本采用 MIT 许可证。双语是可读性改进，不声称英文为社区硬性规定；投稿时再核对 [官方提交说明](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin)。

## 验收场景

这些场景用于检查实现，并非声称已完成真人测试：

| 用户目标 | 应从界面得到的答案 |
| --- | --- |
| 只想让某个插件不再同步，想保留本机设置 | 取消勾选并应用；跳过清理即可 |
| 想把本机不用的插件移走，但以后可能要拿回来 | 应用不同步选择，再单独清理；备份仍在且不释放空间 |
| 刚清理错了插件 | 用“找回清理过的插件”，而不是“重新允许同步” |
| 准备不用 Device Selective Sync | 先预览取消它添加的同步限制；停用本身不会取消 |
| 上次操作失败 | 先检查上次操作，再重新预览；不要默认清空记录 |
| 手机看见电脑新装的插件 | 手机读到的是上次保存的清单，不代表已经安装或启用 |
| 手机上保存选择后想立刻改 iPad | 先等 Sync 完成，再到 iPad 刷新和编辑 |
| 切换到英文 | 操作含义一致，没有剩余的主要中文说明 |

真实手机、小屏幕、辅助阅读和首次使用者访谈仍是后续工作。自动测试只能验证界面状态和行为，不能证明普通用户已经理解。
